.. _overview:

总览、术语与翻译模型
====================

文档范围
--------------------------------------------------------------------------------

本文档同时承担两个角色：

1. **语言规范**\ ：定义结绳源文件的词法、语法、类型、隐式转换、语法糖与语义等价性规约。
2. **实现说明**\ ：描述 FTC 的 AST/IR、Pass 管线、Java 代码生成策略，以及 Android/JVM 两个平台的实际产出。

规范条款只覆盖当前编译器支持的子集。任何“未实现/仅解析”的构造都在正文标注，并在 :doc:`../appendix/divergences` 汇总。

自包含性
--------------------------------------------------------------------------------

本文档不引用仓库外的文档、规范、链接或示例。所有源码路径均为仓库相对路径，例如 ``src/frontend/parser.cpp``\ 。标准库类型映射来自 ``stdlibs/``\ 下的 ``@指代类``\ 声明，而不是编译器硬编码。

术语
--------------------------------------------------------------------------------

.. list-table:: 术语表
   :header-rows: 1
   :widths: 18 82
   :name: table-terminology

   * - 术语
     - 含义
   * - 编译单元（Unit）
     - 一个 ``.t``\ 文件解析后的顶层结构，包含包名、注解与类声明。
   * - AST
     - parser 直接构造的语法树，定义在 ``src/ir/ast.h``\ ；在本编译器中 AST 同时充当 IR。
   * - lowered IR
     - 低于 AST 的中间表示（三地址码、SSA、字节码等）。本编译器没有这种 IR。
   * - 核心语义
     - 直接用目标 Java 结构表达、不可再去除的语义，例如类/方法/字段、控制流、显式转换。
   * - 语法糖
     - 可改写为更小核心结构的源语法，例如属性访问、事件、运算符重载、默认参数、三种循环、异步。
   * - 脱糖（desugaring）
     - 把语法糖改写为核心语义的过程。本编译器绝大多数脱糖发生在 **Java 发射期**\ ，不是独立的翻译前 pass。
   * - 宿主逃逸
     - ``code``/ ``@code``/ ``#...``\ 文本、``@指代类``\ 外部类型、平台注解；语言语义不覆盖其内部。
   * - 目标扩展
     - 由平台/语言目标注册表提供的附加能力，例如 Android 资源与清单、JVM 控制台。
   * - 输出计划（OutputPlan）
     - 按需输出算法产生的类/成员集合，决定最终发射哪些声明。
   * - 事实（facts）
     - 注解在 Declare 阶段写入 ``SemanticModel``\ 的元数据，例如 ``async``\ 、``hidden``\ 、``output_name``\ 。
   * - 效果（effects）
     - 注解在 Apply 阶段写入 ``EffectStore``\ 的目标相关数据，例如 ``JavaModifiers``\ 、``AndroidManifestSpecs``\ 。

翻译模型
--------------------------------------------------------------------------------

编译器的高层数据流如下（没有独立的 lowered IR）：::

    .t 源文件
      → Lexer（Token 流）
      → Parser（Unit / ClassDecl / Member / Stmt / Expr，AST 即 IR）
      → 注解阶段（校验、@编译条件、Declare → SemanticModel）
      → SymbolTable（类/成员解析）
      → Apply 注解与平台需求（EffectStore、PlanHints）
      → ComputeOutputPlan（按需输出）
      → JavaLanguageBackend::Emit（AST → EmittedText，绝大部分脱糖在这里）
      → PlatformBackend::Generate（写 Java、清单、资源、Gradle、metadata）

这意味着：

- “翻译前脱糖”只适用于少量解析期归一化（例如顶层语句合成类、``[]``/``[]=``\ 方法名、else 链嵌套）。
- 属性、事件、运算符重载、默认参数、foreach、泛型特化、异步状态机等，都是 **发射期**\ 将 AST 直接改写为 Java 文本。
- 因此语义等价性必须按“源 AST 与最终 Java 文本”的关系来定义，而不是假设存在一个统一的核心 IR。

源语言与目标语言
--------------------------------------------------------------------------------

- 源语言：结绳，中文上下文关键字，类/方法/字段/属性/事件模型，单继承。
- 目标语言：Java 与 C++。Java 后端面向 ``android``/``jvm``\ 平台；C++ 后端面向 ``cxx`` 平台，产出 C++17 工程与 CMake/编译脚本（见 :doc:`platform/cxx`）。
- Java 平台共用 Java 语言后端，平台差异由 ``PlatformExtension``\ 提供。
- Java 版本基线：Gradle 模板使用 Java 11；JVM 平台只要求能编译生成源码的 JDK。C++ 基线为 C++17。

记号约定
--------------------------------------------------------------------------------

- EBNF：``=``\ 定义，``|``\ 选择，``[ ... ]``\ 可选，``{ ... }``\ 重复，``( ... )``\ 分组，``"..."``\ 终结符。
- 类型判断：``Γ ⊢ e : T``\ 表示在环境 ``Γ``\ 下表达式 ``e``\ 具有类型 ``T``\ 。
- 转换判断：``Γ ⊢ e : T ⇝ e′ : U``\ 表示 ``e``\ 被转换为目标类型 ``U``\ ，生成目标表达式 ``e′``\ 。
- 翻译关系：``⟦s⟧``\ 表示源结构 ``s``\ 的目标 Java 形态；等价性是条件性的，见 :doc:`../language/semantics`。
- 状态：``已实现``/ ``受限``/ ``未实现/仅解析``\ ，含义见 :ref:`index`。

标准库加载模型
--------------------------------------------------------------------------------

类型映射不是编译器内置的。标准库通过 ``@指代类("Java类型")``\ 声明源类型与 Java 类型的对应关系；``JavaTypeMapper::MapType``\ 在符号表中解析源类型并读取该声明。

推荐加载方式：

.. list-table:: 推荐标准库组合
   :header-rows: 1
   :widths: 12 44 44
   :name: table-stdlib-sets

   * - 目标
     - 源文件
     - 说明
   * - Android
     - ``stdlibs/安卓基本库/源代码/**/*.t``
     - 含 ``Java/JVM_基本类型.t``\ 、``Java/JVM_基本数据结构.t``\ 与 Android 组件/资源库；包名 ``结绳.基本``\ 、``结绳.JVM``\ 、``结绳.安卓``\ 等。
   * - JVM
     - ``stdlibs/安卓基本库/源代码/Java/JVM_基本类型.t`` + ``stdlibs/JVM基本库/源代码/*.t``
     - 叠加 ``控制台``\ 、``JVM_调试``\ 、``JVM_兼容类型``\ ；不加载 Android 组件/资源库。

注意事项：

- 标准库不会自动加载；未加载对应声明时，类型/成员会报缺失或未解析错误，编译不会写出产物。
- ``@全局基础类``\ 只能有一个；当前标准库中 ``对象``\ 是全局基础类。
- 同一简单名可能在多个包中重复。例如 ``集合``\ 同时出现在 ``结绳.JVM``\ （``JVM_基本数据结构.t``\ ）与 ``结绳.基本``\ （``JVM_兼容类型.t``\ ）；同时加载会导致简单名索引歧义，并可能在标准库内部触发类型/禁止创建对象错误。应按目标只加载一套。
- 成员、局部变量与泛型实参中的未解析类型会报错并停止生成；完整编译应在加载正确标准库后执行。
- 目标平台要求（requirements）会在符号表建立后检查缺失类型/成员，缺失即致命错误。

FTC 默认修正与兼容开关
--------------------------------------------------------------------------------

FTC 默认启用与参考实现不同的修正：

- 泛型特化输出合法 Java 类名 ``类名$实参``\ ，而不是参考实现的 ``类名<实参>``\ ；
- 运算符重载输出合法方法名 ``operator_*``\ ，而不是 ``[]``/``==`` 等非法 Java 标识符；
- 内联 code 语句缺少 ``;``/``}`` 时自动补分号；
- 类 ``@输出名`` 与输出路径做安全校验。

``--disable-ftc-features`` 关闭这些修正：依赖泛型特化、运算符重载方法名、内联 code 自动补分号、map 键值遍历、负步长、对象下标交换、重复订阅或原始类型事件默认值的代码会报错（``compat.ftc.*``），而不是生成参考实现的非法 Java 产物。输出目录包含检查是安全边界，始终启用。

如果考虑与参考实现严格兼容，建议禁用该开关；禁用后应修正相关构造或接受明确错误。详见 :doc:`appendix/divergences`。

文档约定
--------------------------------------------------------------------------------

- 所有源码锚点使用仓库相对路径与函数名；行号仅在必要处给出，可能随重构漂移。
- 所有 Tiecode 代码块使用 ``text``\ 高亮；Java 代码块使用 ``java``\ ；语法使用 ``ebnf``\ 。
- 表格中的“状态”列使用 :ref:`table-status-legend` 的三种值。
- 受限项必须能指向源码或测试；无法给出依据的行为不写入规范。

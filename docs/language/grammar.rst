.. _grammar:

语法规范
========

本节以 EBNF 描述当前 parser 接受的结绳语法。实现位于 ``src/frontend/parser.cpp``\ 。由于 parser 是手写递归下降、使用单 Token 前瞻与有序选择，部分歧义不能只靠 EBNF 表达；文末给出 PEG 风格的识别策略与终止符规则。

.. contents:: 目录
   :local:
   :depth: 2

记号
--------------------------------------------------------------------------------

- ``=``\ 定义；``|``\ 选择；``[ ... ]``\ 可选；``{ ... }``\ 重复；``( ... )``\ 分组。
- ``"..."``\ 是终结符（中文关键字按原样书写）。
- ``IDENT``\ 、``STRING``\ 、``INT``\ 等是词法记号，见 :ref:`lexical`。
- ``SYMBOL``\ 表示任意 ``kSymbol`` Token（parser 允许用符号作为方法名）。
- 注释 ``(* ... *)``\ 不属于语言语法。

编译单元、包与注解
--------------------------------------------------------------------------------

.. code-block:: text

   unit            = { unit_item } ;
   unit_item       = { annotation } ( package_decl | class_decl | top_level_item ) ;
   package_decl    = "包名" IDENT { "." IDENT } ;
   top_level_item  = member | statement ;   (* 仅 --enable-toplevel-stmt *)

   annotation      = "@" dotted_name [ "(" [ ann_arg { "," ann_arg } ] ")" ] ;
   dotted_name     = IDENT { "." IDENT } ;
   ann_arg         = [ IDENT "=" ] ann_value ;
   ann_value       = STRING | raw_token_sequence ;

规则与边界：

- ``包名``\ 可重复；后出现的覆盖前面的值。末尾多余的点会被忽略。
- 注解可以写在 ``包名``\ 之前或之后。写在 ``包名``\ 之前的注解进入 ``Unit::annotations``\ ；写在类/成员之前的注解进入对应声明。语句前的注解会被 parser 读取后 **丢弃**\ （``Stmt``\ 没有注解字段）。
- 注解名是点分标识符；未知名称、目标级别、参数形态在注解阶段校验。
- 注解参数：
  - 第一个 Token 是字符串时，记 ``is_string = true``\ ，值为解码后的 ``text``\ ；
  - 否则捕获原始 Token 序列，顶层 ``()``/``[]``/``{}``\ 配对，遇到顶层 ``,``\ 或 ``)``\ 停止；Token 文本 **不加空格**\ 直接拼接；
  - 允许尾随逗号；
  - 缺少 ``)``\ 报 ``注解参数列表缺少 ')'``\ ；
  - ``@布局配置``\ 的参数若包含 ``{``\ 会报 ``此处不应该出现 '{'``\ 。
- ``@code``/``@end``\ 是词法构造，不是注解，不能按注解语法使用。
- 没有 ``import``\ 语法；导入由 ``@导入Java``\ 或类型引用自动收集。

类与成员
--------------------------------------------------------------------------------

.. code-block:: text

   class_decl      = "类" IDENT [ generic_params ] [ ":" type ]
                     { class_item } "结束" "类" ;
   generic_params  = "<" generic_param { "," generic_param } ">" ;
   generic_param   = ( IDENT | STRING ) [ "=" raw_type_tokens ] ;

   class_item      = code_block
                   | { annotation } member_decl ;

   member_decl     = var_decl
                   | method
                   | property_read
                   | property_write
                   | event_definition
                   | event_block ;

   var_decl        = ( "变量" | "常量" ) IDENT [ ":" type ]
                     [ "=" ( expr | code_block ) ] [ ";" ] ;

   method          = "方法" method_name params [ ( ":" | "为" ) type ]
                     ( "=" ( expr | code_block | "..." )
                     | block "结束" "方法" ) ;

   property_read   = "属性读" method_name params [ ( ":" | "为" ) type ]
                     ( "=" ( expr | code_block | "..." )
                     | block "结束" "属性" ) ;

   property_write  = "属性写" method_name params [ ( ":" | "为" ) type ]
                     ( "=" ( expr | code_block | "..." )
                     | block "结束" "属性" ) ;

   event_definition = "定义事件" [ IDENT ] params [ ( ":" | "为" ) type ] ;

   event_block      = "事件" event_object ":" [ IDENT ] params
                      [ ( ":" | "为" ) type ] block "结束" "事件" ;

   event_object     = ( IDENT | "本对象" | "父对象" ) { "." IDENT } ;

   method_name      = IDENT | SYMBOL | "[" "]" [ "=" ] ;

   params           = "(" [ param { "," param } ] ")" ;
   param            = IDENT [ ( ":" | "为" ) type ] [ "=" expr ] ;

   block(term)      = { statement } [ "结束" term ] ;

规则与边界：

- 类声明只支持 **单继承**\ ：``类 X : Y``\ ；没有接口、枚举、结构体、命名空间。
- 类名必需；缺少时报 ``类声明缺少类名``\ 。
- 泛型参数记录名字、是否有默认值以及默认类型文本；默认类型用类型语法解析，使用处会补齐默认实参。缺少 ``>`` 时报错，不再静默消费到 EOF。
- 成员分派顺序：先检查 ``code_block``\ ，因此 **类级 code 块不能被注解**\ ；然后再解析注解与成员。
- 方法名可以是标识符或任意符号。``[]``\ 与 ``[]=``\ 在 parser 中规范化为字符串 ``"[]"``/ ``"[]="``\ ；其他符号（``+``\ 、``=``\ 、``?``\ 等）原样保存。
- 方法体四种形式：块体、``= 表达式``\ （单行方法）、``= code ...``\ 、``= ...``\ （无方法体声明）。
- 属性读/写以 ``结束 属性``\ 结束，不是 ``结束 属性读``/``结束 属性写``\ 。
- ``定义事件``\ 没有方法体，也没有 ``结束``\ 。
- 类级事件块的对象可以是标识符、``本对象``\ 、``父对象``\ ，可带点分后缀；语句级事件块只接受单个标识符对象，且必须有 ``:``\ 。
- 参数默认值是表达式；没有可变参数、命名实参、泛型方法。
- 成员类型分隔符可用 ``:``\ 或 ``为``；**局部变量只接受** ``:``。
- 类体结束前遇到新的 ``类``\ 报 ``类体结束前遇到了新的类声明``\ 。
- 无法识别的成员报 ``无法识别的类成员声明: "..."``\ 并尝试同步到下一个行首声明。

类型
--------------------------------------------------------------------------------

.. code-block:: text

   type            = [ qualified_name ]
                     { "<" type { "," type } ">" }
                     { "[" [ expr ] "]" }
                     { "?" } ;
   qualified_name  = IDENT { "." IDENT } ;

实现补充：

- 类型基名可以为空；parser 不为缺失类型报错。
- 泛型实参、数组容量、可空后缀都作为 **原始文本**\ 保存；泛型实参中的空白被去除。
- 数组容量可以省略；多维数组重复方括号。容量表达式只跟踪圆括号嵌套，不跟踪方括号嵌套。
- ``?``\ 可重复书写，全部作为类型字符串后缀保留；Java 映射会剥离它。
- 没有函数类型、联合类型、通配符、型变标注。
- 完整的类型解析与映射见 :ref:`types`。

语句
--------------------------------------------------------------------------------

.. code-block:: text

   statement       = code_block
                   | { annotation } core_statement
                   | ";" statement ;

   core_statement  = if_stmt
                   | switch_stmt
                   | loop_stmt
                   | return_stmt
                   | var_stmt
                   | break_stmt
                   | continue_stmt
                   | subscribe_stmt
                   | event_stmt
                   | expr [ ";" ] ;

   if_stmt         = "如果" expr [ "则" ] { statement }
                     [ else_part ] "结束" "如果" ;

   else_part       = "否则" if_stmt
                   | "否则" expr [ "则" ] { statement } [ else_part ]
                   | "否则" { statement } ;

   switch_stmt     = "假如" expr { case_clause }
                     [ "否则" { statement } ] "结束" "假如" ;
   case_clause     = "是" expr { "," expr } { statement } ;

   loop_stmt       = "循环" "(" IDENT "," [ expr ] "," [ expr ]
                       [ "," [ expr ] ] ")" block("循环")
                   | "循环" "(" expr "->" [ IDENT [ "," IDENT ] ] ")"
                       block("循环")
                   | "循环" "(" expr ")" block("循环") ;

   return_stmt     = "返回" [ "(" ")" ] [ expr ] [ ";" ] ;
   var_stmt        = ( "变量" | "常量" ) IDENT [ ":" type ]
                     [ "=" ( expr | code_block ) ] [ ";" ] ;
   break_stmt      = "退出循环" ;
   continue_stmt   = "跳过循环" ;

   subscribe_stmt  = "订阅事件" [ "(" ")" ] [ IDENT ] ;
   event_stmt      = "事件" IDENT ":" [ IDENT ] params
                     [ ":" type ] block("事件") ;

规则与边界：

- 分号几乎都可省略；空语句 ``;``\ 会被跳过。
- ``如果``\ 的 ``则``\ 可选；``否则``\ 后面如果同行出现表达式，会按“否则条件”解析（``ParseIfConditional``\ ）；否则按 else 块解析。
- ``否则`` 后同行出现条件时按“否则条件”解析（``ParseIfConditional``）；``否则 如果`` 走递归 ``ParseIf``，内层消费唯一的 ``结束 如果``，外层直接返回。两种写法都只需要一个终止符；额外再写一个 ``结束 如果`` 是错误语法。见 :ref:`grammar-else-if`。
- ``假如``\ ：``是``\ 后可跟一个或多个逗号分隔的表达式；每个 case 的语句在下一个 ``是``/``否则``/``结束 假如``\ 处结束；没有 fallthrough 语法，emitter 会为每个 case 自动插入 ``break``\ 。
- ``循环``\ 三种形式由前瞻决定：
  - ``循环``\ 后是 ``IDENT ,`` → 计次循环；开始/结束/步长都可省略，但第二个逗号必需；``循环(i, 0)``\ 不合法，``循环(i, , 10)``\ 合法。
  - 先解析表达式，若后面是 ``->`` → 遍历循环；可选的键/值变量，第二变量当前被 emitter 忽略。
  - 否则 → 条件循环。
- ``返回``\ ：``返回()``\ 是空返回；其他情况下 ``返回 (表达式)``\ 是带括号的返回表达式。表达式在 ``结束``\ 、``否则``\ 、``是``\ 、``;``\ 或 EOF 前可省略。
- ``订阅事件``\ 可带空 ``()``\ 和可选目标标识符（仅同一行）；目标表达式会被 emitter 忽略，实际发射类内所有事件块。
- 语句级事件块的检测条件是 ``事件 IDENT :``\ ；只接受单个标识符对象，返回类型分隔符只接受 ``:``\ 。
- 语句前的注解会被 parser 读取后丢弃，不会影响语句。
- ``结束``\ 的行为是上下文相关的，见 :ref:`grammar-terminators`。

表达式与优先级
--------------------------------------------------------------------------------

.. code-block:: text

   expr            = assignment ;
   assignment      = logical_or { ( "=" | "<=>" ) assignment } ;

   logical_or      = logical_and { ( "或" | "||" ) logical_and } ;
   logical_and     = bitwise { ( "且" | "&&" ) bitwise } ;
   bitwise         = equality { ( "|" | "&" | "^" ) equality } ;
   equality        = comparison { ( "==" | "!=" ) comparison } ;
   comparison      = additive { ( "<" | ">" | "<=" | ">=" | "?" ) additive } ;
   additive        = multiplicative { ( "+" | "-" ) multiplicative } ;
   multiplicative  = cast_level { ( "*" | "/" | "%" ) cast_level } ;
   cast_level      = unary { ( ":" type | "属于" type ) } ;

   unary           = ( "-" | "+" ) unary
                   | "创建" type [ "(" ")" ]
                   | "等待" unary
                   | postfix ;

   postfix         = primary { "." ( IDENT | SYMBOL )
                             | "(" [ call_arg { "," [ call_arg ] } ] ")"
                             | "[" expr "]" } ;

   primary         = literal
                   | "真" | "假" | "空" | "本对象" | "父对象"
                   | IDENT
                   | "(" expr [ "," [ expr { "," expr } ] ] ")"
                   | "{" [ expr { "," expr } ] "}" ;

   call_arg        = expr ;

优先级从低到高：

.. list-table:: 优先级与结合性
   :header-rows: 1
   :widths: 8 36 24 32
   :name: table-precedence

   * - 级别
     - 运算
     - 结合性
     - 说明
   * - 1
     - ``=``\ 、``<=>``
     - 右
     - 赋值/交换；``<=>``\ 只在语句位置由 emitter 特殊处理。
   * - 2
     - ``或``\ 、``||``
     - 左
     - 逻辑或。
   * - 3
     - ``且``\ 、``&&``
     - 左
     - 逻辑与。
   * - 4
     - ``|``\ 、``&``\ 、``^``
     - 左
     - 三者同级；按位或/与/异或。
   * - 5
     - ``==``\ 、``!=``
     - 左
     - 相等/不等。
   * - 6
     - ``<``\ 、``>``\ 、``<=``\ 、``>=``\ 、``?``
     - 左
     - ``?``\ 是二元比较级运算符，不是三元。
   * - 7
     - ``+``\ 、``-``
     - 左
     - 加/减/字符串拼接。
   * - 8
     - ``*``\ 、``/``\ 、``%``
     - 左
     - 乘/除/取模。
   * - 9
     - ``:``\ 转换、``属于``
     - 左
     - 类型转换/类型测试；优先级高于乘除。
   * - 10
     - 前缀 ``-``\ 、``+``\ 、``创建``\ 、``等待``
     - 右
     - 一元。
   * - 11
     - ``.``\ 、调用 ``()``\ 、下标 ``[]``
     - 左
     - 后缀。
   * - 12
     - primary
     - —
     - 字面量、标识符、括号、数组字面量等。

表达式规则与边界：

- ``创建 T``/ ``创建 T()``\ 合法；``创建 T(args)``\ 会报 ``此处需要')'``\ 与 ``该表达式为孤立表达式，不是完整的表达式``\ ，并且仍返回无参 ``kNew``\ 。
- ``(expr)``\ 是括号；``(a, b)``\ 产生 ``kMulti``\ ；``(a,)``\ 也产生一个子节点的 ``kMulti``\ 。调用实参中展开为多个实参；初始化器中若目标类有 ``=`` 运算符则调用 ``operator_assign(a, b)``；其他位置会输出逗号表达式，Java 不支持。
- ``{...}``\ 是数组字面量；空数组、尾随逗号都允许。初始化器上下文发射为 ``new T[]{...}``\ ；其他表达式位置按元素嵌套深度发射 ``new Object[]{...}``\ ，保证仍是合法 Java 表达式。
- 调用参数允许空洞：``f(,)``\ 、``f(,a)``\ 会在 ``children``\ 中插入 ``nullptr``\ ，发射时按默认参数/``null``\ 处理。
- 字段访问的成员名可以是标识符或任意符号；``member_position``\ 记录成员位置。
- ``等待``\ 是一元前缀；是否可用由后端/lint 决定，见 :ref:`semantics`。
- 没有三元 ``?:``\ 、lambda、字符串插值、map 字面量、后缀自增/自减、逻辑非 ``!``\ 。
- ``?``\ 作为可空类型后缀只在类型位置；作为表达式运算符时按二元运算发射。

``@编译条件``\ 子语言
--------------------------------------------------------------------------------

``@编译条件``\ 的参数不由主 parser 解析，而是由 ``src/ir/compile_conditions.cpp``\ 的独立小 parser 求值。其语法为：

.. code-block:: text

   cond_expr    = cond_or ;
   cond_or      = cond_and { "或" cond_and } ;
   cond_and     = cond_unary { "且" cond_unary } ;
   cond_unary   = "非" cond_unary | cond_primary ;
   cond_primary = "(" cond_expr ")"
                | ( "已定义" | "未定义" ) "(" [ name ] ")"
                | "真" | "假" | name ;
   name         = name_char { name_char } ;
   name_char    = ascii_letter | ascii_digit | "_" | "." | non_ascii_byte ;

规则：

- ``已定义``/``未定义``\ 与 ``(``\ 之间允许空白；名字可以用单/双引号包裹，不支持转义。
- 普通名字与运算符之间的空格不会被跳过，因此 ``a 或 b``\ 可能解析失败。
- ``或者``\ 会被标记为非法；逻辑或写 ``或``\ 。
- 条件只允许出现在类/变量/方法级别（``kAnyMember``\ ）；写在编译单元（``包名``\ 前）会报目标级别错误。
- 默认定义：``调试版`` = 非 ``--release``\ ，``正式版`` = ``--release``\ ；``-d name=value``\ 中的值按“非 ``假``/``false``/``0``\ 即真”归一为布尔。
- 条件为假的类/成员会在 Declare 之前被裁剪；注解校验先于裁剪，因此被裁剪声明上的其他注解仍会被校验。

识别策略（PEG 风格）
--------------------------------------------------------------------------------

parser 是递归下降 + 单 Token 前瞻，不进行一般回溯。关键有序选择如下：

.. list-table:: 关键前瞻与有序选择
   :header-rows: 1
   :widths: 24 76
   :name: table-peg-choices

   * - 位置
     - 选择规则
   * - 类体成员
     - 先匹配 ``code``/``@code``\ 块；否则解析注解；再按 ``变量/常量/方法/属性读/属性写/定义事件/事件``\ 顺序匹配。
   * - 语句
     - 先匹配 code 块；再跳过注解；再按 ``如果/假如/订阅事件/循环/返回/变量/常量/退出循环/跳过循环/事件 ident:/表达式``\ 顺序匹配。
   * - 循环
     - ``循环``\ 后若为 ``IDENT ,`` → 计次；否则解析表达式，若后跟 ``->`` → 遍历；否则 while。
   * - 如果的否则
     - ``否则``\ 同行有表达式 → 否则条件；否则 → else 块；``否则 如果`` → 递归 if。
   * - 类型
     - 可空基名 + 循环消费 ``<...>``\ 、``[...]``\ 、``?``\ 。
   * - 事件
     - 类级 ``事件``\ 后接受对象表达式；语句级只接受 ``事件 IDENT :``\ 。
   * - 顶层
     - 未开启 ``--enable-toplevel-stmt``\ 时只接受 ``类``\ ；开启后语句被折叠进合成类。

.. _grammar-terminators:

块与终止符
--------------------------------------------------------------------------------

- ``ParseBlock``\ 用于方法体、属性体、循环体、事件块体：
  - 遇到 ``结束 <terminator>``\ 时消费两个 Token 并返回；
  - 遇到裸 ``结束``\ 时直接返回，**不消费**\ ，由外层继续处理。
- ``如果``\ 使用自己的语句循环，只接受 ``结束 如果``\ ；裸 ``结束``\ 不能可靠关闭它。
- ``假如``\ 只接受 ``结束 假如``\ ；裸 ``结束``\ 不能可靠关闭它。
- ``方法``\ 的终止符是 ``方法``\ ；属性读/写都是 ``属性``\ ；循环是 ``循环``\ ；事件块是 ``事件``\ ；类是 ``类``\ 。
- 空语句 ``;``\ 递归跳到下一条语句。
- 最后一个成员可以省略自己的 ``结束 方法``\ ，由 ``结束 类``\ 隐式结束；但这依赖 ``ParseBlock``\ 的裸 ``结束``\ 行为，容易产生级联错误，建议总是写完整终止符。

.. _grammar-else-if:

``否则 <条件>`` 与 ``否则 如果``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``否则`` 支持两种 else-if 写法，二者都只需要一个 ``结束 如果``。

同行条件（推荐）：

.. code-block:: text

   如果 a
      语句
   否则 b
      语句
   结束 如果

``否则 如果`` 递归形式：

.. code-block:: text

   如果 a
      语句
   否则 如果 b
      语句
   结束 如果

内层 ``ParseIf`` 消费唯一的 ``结束 如果``，外层直接返回。**不要写两个终止符**：

.. code-block:: text

   如果 a
      语句
   否则 如果 b
      语句
   结束 如果
   结束 如果

最后一个 ``结束 如果`` 是多余且错误的语法，会触发解析诊断。

解析器诊断与恢复
--------------------------------------------------------------------------------

.. list-table:: 主要 parser 诊断
   :header-rows: 1
   :widths: 42 58
   :name: table-parse-diagnostics

   * - 消息
     - 触发条件/恢复
   * - ``期望 <what>，实际遇到 "<text>"``
     - ``Expect``/``ExpectSymbol``\ 失败；继续尝试解析。
   * - ``源文件中只允许类声明，遇到 "<text>"``
     - 未开启顶层语句模式且遇到非类声明；跳到下一个 ``类``\ 。
   * - ``注解缺少名称``
     - ``@``\ 后没有标识符。
   * - ``注解参数列表缺少 ')'``
     - 注解参数未闭合。
   * - ``此处不应该出现 '{'``
     - ``@布局配置``\ 参数包含属性表。
   * - ``类声明缺少类名``
     - ``类``\ 后不是标识符。
   * - ``类体结束前遇到了新的类声明``
     - 类体中出现新的 ``类``\ 。
   * - ``变量声明缺少名称``
     - ``变量``/``常量``\ 后没有标识符。
   * - ``无法识别的类成员声明: "<text>"``
     - 成员分派失败；同步到下一个列 0 的声明。
   * - ``方法声明缺少名称``
     - ``方法``\ 后没有名称。
   * - ``参数缺少名称``
     - 参数列表中出现非标识符。
   * - ``假如语句中期望 "是"、"否则"或"结束 假如"``
     - switch 结构错误。
   * - ``此处需要')'``\ 、``该表达式为孤立表达式，不是完整的表达式``
     - ``创建 T(args)``\ 的参数。
   * - ``无法解析的表达式: "<text>"``
     - primary 失败；消费一个 Token 并返回 ``kUnknown``\ 。

恢复注意：

- ``SynchronizeToDeclaration``\ 只在 ``begins_line == true``\ （列 0）处停下；缩进成员出错时可能一直同步到 EOF。
- ``ParseBlock``\ 遇到裸 ``结束``\ 时不消费；错误可能延迟到外层，表现为 ``期望 '类'``/``期望 '方法'``\ 等级联消息。
- parser 返回 ``false``\ 只表示诊断数增加；源加载仍会把 Unit 推入程序，后续阶段可能继续报错。

实现细节与建议
--------------------------------------------------------------------------------

- 可读性优先：中文词之间保留空格；不要写 ``结束类``\ 。
- 方法/属性/循环/事件块写完整终止符，避免依赖裸 ``结束``\ 。
- else-if 使用 ``否则 <条件>`` 或 ``否则 如果``，只写一个 ``结束 如果``；不要重复终止符。
- 遍历循环不要依赖第二变量；见 :ref:`sugar-foreach`。
- ``创建``\ 不要写构造参数；见 :ref:`divergence-create-args`。
- 语句注解不会生效；需要注解时把它放在成员/类声明上。
- 类级 ``code``\ 块不能加注解；需要注解时改用方法/字段。

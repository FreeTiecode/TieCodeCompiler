设计范围（不是缺陷）
--------------------

.. _divergence-language-scope:

语言特性范围
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当前语言规范不包含以下构造；它们不是“漏实现”，而是不在本编译器的语言范围内：

- 接口、枚举、结构体、命名空间、模块；
- 异常处理语法（``try``/``catch``/``throw``）；
- lambda、匿名类语法（只能写在 ``code`` 中）；
- 三元 ``?:``、一元 ``!``、``++``/``--``、复合赋值、移位；
- 方法级泛型、泛型约束、通配符/型变；
- 字符串插值、map 字面量、模式匹配；
- 访问修饰符（只有 ``@隐藏`` 省略 ``public``）；
- 包导入语法（用 ``@导入Java``）。

.. _divergence-create-args:

``创建 T(args)`` 只支持空括号
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

语言规范明确要求 ``创建 类型``/``创建 类型()`` 只使用空括号；需要构造参数时使用 ``=`` 运算符重载、多元表达式或自动创建规则。因此 ``创建 T(args)`` 会报解析错误，这不是待修复缺陷。

.. _divergence-else-if:

``否则`` 与 ``否则 如果``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``否则 <条件>`` 与 ``否则 如果`` 都是正确的 else-if 写法，均只使用一个 ``结束 如果``；额外重复 ``结束 如果`` 才是错误语法。

.. _divergence-types-names:

``短整数`` 与 ``逻辑``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- 当前没有 ``短整数`` 类型；有 ``字节``、``字符``、``整数``、``长整数``、``单精度小数``、``小数``。
- 布尔类型名是 ``逻辑型``，不是 ``逻辑``；``逻辑`` 不是标准库别名。

关键项详解
----------

.. _divergence-multi-expression:

多表达式的上下文
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``(a,b)`` 在调用实参中展开为多个实参；在字段/局部变量/返回值等初始化器中，如果目标类定义了 ``=`` 运算符，会发射 ``目标.operator_assign(a, b)``。
- 其他表达式位置会输出裸逗号表达式；Java 不接受这种表达式，因此应在调用、初始化器或构造参数中使用。
- 数组字面量 ``{...}`` 已在初始化器上下文发射为 ``new T[]{...}``；其他位置按嵌套深度发射 ``new Object[]{...}``，不会输出裸花括号。

.. _divergence-async-loop-await:

异步循环头部的等待
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``@异步方法`` 支持循环体内的 ``等待``，foreach 会降级为迭代器状态机。但以下位置尚未状态化：

- 计次循环的 ``begin``/``end``/``step`` 表达式中的 ``等待``；
- foreach 集合表达式本身的 ``等待``。

这两种情况会明确报 ``codegen.async-loop-await`` 或 ``codegen.async-foreach-await``，不会静默生成错误状态机。替代：把等待结果先赋给局部变量，再进入循环。

.. _divergence-no-pointer:

``@禁用指针``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``NoPointerAnnotation::Declare`` 记录类 facts ``disable_pointer``；当前 Java/Android/JVM 后端没有对应的指针式输出策略需要关闭，因此该 fact 不改变产物。需要隐藏类时使用 ``@隐藏``\ ，需要禁止创建时使用 ``@禁止创建对象``\ 。

.. _divergence-double-collection:

同时加载两套 ``集合``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``结绳.JVM.集合``（``JVM_基本数据结构.t`` → ``ArrayList``）与 ``结绳.基本.集合``（``JVM_兼容类型.t`` → ``List``）简单名相同。同时加载时简单名索引歧义；实测还会在标准库内部先触发类型/禁止创建对象错误。

替代：Android 只加载 ``安卓基本库``；JVM 只加载 ``JVM_基本类型.t`` + ``JVM基本库``。

.. _divergence-dump-ast:

``--dump-ast`` 的能力
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

只输出文件/包/类/成员名与语句数量，不输出表达式树/优先级/脱糖结果。需要检查 AST 形状时直接阅读 parser 或生成 Java。

.. _divergence-no-cleanup:

输出目录不清理
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

编译器不会删除输出目录中的旧文件；重命名/删除类后旧 ``.java`` 可能残留。建议编译前清空输出目录。

.. _divergence-platform-cli:

被忽略的 CLI 选项
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当前接受但忽略：``--source``、``--keep-defaults``、``--optimize``、``--log-level``、``--android.legacy.lib.path``。不要依赖它们改变产物。

FTC 默认修正与兼容开关
----------------------

FTC 默认启用以下与参考实现不同的修正；不禁用时，编译器会按 FTC 规则生成可构建、输出安全的产物：

.. list-table:: FTC 默认修正
   :header-rows: 1
   :widths: 26 40 34
   :name: table-ftc-compat

   * - 修正项
     - 默认行为（不禁用）
     - ``--disable-ftc-features`` 时
   * - 泛型特化命名
     - 使用合法 Java 类名 ``类名$实参``\ ，文件名/import/调用点一致
     - 使用泛型类或特化时报 ``compat.ftc.generic``
   * - 运算符方法名
     - 映射为 ``operator_*``\ 合法 Java 方法名
     - 使用运算符重载方法时报 ``compat.ftc.operator``
   * - 内联 code 语句
     - 缺少 ``;``/``}`` 时自动补分号
     - 缺少结尾时报 ``compat.ftc.inline-semicolon``
   * - map 键值遍历
     - 发射 ``entrySet()``/``getKey()``/``getValue()``
     - 使用键值遍历会报错（可能先命中泛型检查）
   * - 负步长计次循环
     - 使用 ``>`` 条件，支持倒序
     - 静态负步长报 ``compat.ftc.negative-step``
   * - 对象下标交换
     - 读取两侧值并分别写回两侧下标
     - 使用两侧对象下标交换时报错（可能先命中运算符检查）
   * - 重复订阅事件
     - 同一方法内去重，只注册一次
     - 第二次 ``订阅事件`` 报 ``compat.ftc.subscriptions``
   * - 原始类型事件默认值
     - ``字符``/``字节``/``短整数`` 返回零值
     - 此类事件报 ``compat.ftc.event-default``
   * - 输出路径安全
     - 类 ``@输出名`` 必须合法，且写入限制在输出目录内
     - **始终启用**\ ；安全边界不随兼容开关关闭

如果考虑与参考实现兼容，建议加 ``--disable-ftc-features``。禁用后，依赖上述 FTC 命名/分号修正的代码会显式报错，而不会退化为参考实现的非法 Java 产物或路径穿越。输出目录包含检查是安全边界，始终生效。

局部变量默认值、整数折叠、八进制字面量、``@属性读``/``@属性写`` 注解形式、数组 ``.长度``、异步条件/``假如``、异步 foreach、泛型默认实参、类级 ``@隐藏``、``@废弃使用`` 提示、未解析类型诊断等规范支持的修正默认启用，不属于该兼容开关的范围。

设计行为（不是缺陷）
--------------------

.. _divergence-create-args:

``创建 T(args)`` 只支持空括号
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

父规范明确要求 ``创建 类型``/``创建 类型()`` 只使用空括号；需要构造参数时使用 ``=`` 运算符重载、多元表达式或自动创建规则。因此 ``创建 T(args)`` 会报解析错误，这不是待修复缺陷。

- ``否则 条件`` 是父规范写明的 else-if 形式；``否则 如果`` 是额外的解析扩展，当前需要两个 ``结束 如果``，建议改用前者。
- ``@废弃使用`` 的“可产生提示”、类级 ``@隐藏`` 的可见性、``@禁用指针`` 的平台策略属于参考实现没有强制消费的语义；当前实现记录 facts，不改变 Java 产物。

关键项详解
----------

.. _divergence-else-if:

``否则 如果`` 的双终止符
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``ParseIf`` 在 ``否则 如果`` 分支递归调用自身，内层消费一个 ``结束 如果``，外层再消费一个。因此：

.. code-block:: text

   如果 a
      语句
   否则 如果 b
      语句
   结束 如果
   结束 如果

只写一个终止符会报错。替代写法：

.. code-block:: text

   如果 a
      语句
   否则 b
      语句
   结束 如果

锚点：``src/frontend/parser.cpp`` 的 ``ParseIf``。

.. _divergence-deprecated:

``@废弃使用`` 与 ``@禁用指针``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

两者只写 facts：

- ``@废弃使用`` 记录 ``deprecated``；没有警告消费者。
- ``@禁用指针`` 记录 ``disable_pointer``；没有 emitter 消费者。

.. _divergence-class-hidden:

类级 ``@隐藏``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``HiddenAnnotation::Declare`` 记录类 facts，但 ``EmitClass`` 始终输出 ``public class``；只有成员级 ``@隐藏`` 才省略 ``public``。

.. _divergence-generic-defaults:

泛型默认值
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

parser 记录泛型参数名与“是否有默认值”，lint 只检查 arity/默认值覆盖；使用处不会自动补默认实参。裸 ``集合``/``遍历器`` 可能原样输出为 Java 原始类型。

替代：显式写全泛型实参。

.. _divergence-constant-inline:

常量表达式内联
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

同类常量且带 ``expression_body`` 时，使用处直接发射表达式，而不是读取 ``final`` 字段。若表达式包含 ``创建``/方法调用，每次使用都会重新求值，可能改变对象身份/副作用。

替代：需要稳定对象时用字段初始化，不要用常量表达式内联。

.. _divergence-missing-features:

语言特性缺口
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当前没有：

- 接口、枚举、结构体、命名空间、模块；
- 异常处理语法（``try``/``catch``/``throw``）；
- lambda、匿名类语法（只能写在 ``code`` 中）；
- 三元 ``?:``、一元 ``!``、``++``/``--``、复合赋值、移位；
- 方法级泛型、泛型约束、通配符/型变；
- 字符串插值、map 字面量、模式匹配；
- 访问修饰符（只有 ``@隐藏`` 省略 ``public``）；
- 包导入语法（用 ``@导入Java``）。

.. _divergence-statement-annotations:

语句注解与类级 code 块
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- 语句前的注解会被 parser 读取后丢弃；``Stmt`` 没有注解字段。
- 类级 ``code`` 块在注解解析之前被识别，因此不能被注解。

.. _divergence-array-literal-context:

数组字面量与多表达式的上下文
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``{...}`` 只在初始化器上下文被包装为 ``new T[]{...}``；普通表达式输出裸 ``{...}``。
- ``(a,b)`` 只在调用实参/构造转换中展开；其他位置输出逗号表达式，Java 不支持。
- 多表达式可含 ``nullptr`` 空洞，后端需处理。

.. _divergence-break-outside:

循环外的跳转
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``退出循环``/``跳过循环`` 直接发射 ``break;``/``continue;``；lint 不保证检查上下文。循环外使用会生成非法 Java。

.. _divergence-instanceof-primitive:

原始类型 ``属于``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``值 属于 整数`` 发射 ``value instanceof int``，不是合法 Java。``instanceof`` 只适用于引用类型。

.. _divergence-async-foreach:

异步 foreach
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``@异步方法`` 中的 ``循环(集合 -> 项)`` 没有专门状态机；只有循环前后的语句会被状态化，循环体内的等待不会按 foreach 语义提升。``假如``、``如果``/while 条件等待已支持。

替代：改写成计次循环，或把遍历体放入独立方法。

.. _divergence-code-end:

``@end`` 与 ``obj.code``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- ``@end`` 不要求行首：在任意位置跳过空格/tab 后遇到 ``@end`` 即可终止；字符串中的 ``@end`` 也会终止。
- ``code`` 不要求行首：``obj.code`` 在行尾会被识别为代码块。
- 未闭合的块注释/长字符串不报错。

.. _divergence-double-collection:

同时加载两套 ``集合``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``结绳.JVM.集合``（``JVM_基本数据结构.t`` → ``ArrayList``）与 ``结绳.基本.集合``（``JVM_兼容类型.t`` → ``List``）简单名相同。同时加载时简单名索引歧义；实测还会在标准库内部先触发类型/禁止创建对象错误。即使绕过，未解析的类型也可能原样透传。

替代：Android 只加载 ``安卓基本库``；JVM 只加载 ``JVM_基本类型.t`` + ``JVM基本库``。

.. _divergence-check:

``--check`` 的深度
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``--check`` 在注解阶段后返回：

- 做源加载/解析/注解校验/条件编译/Declare/禁止创建校验；
- 不做符号表、lint、类型检查、代码生成。

不要用 ``--check`` 通过来判断产物可编译。

.. _divergence-dump-ast:

``--dump-ast`` 的能力
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

只输出文件/包/类/成员名与语句数量，不输出表达式树/优先级/脱糖结果。需要检查 AST 形状时直接阅读 parser 或生成 Java。

.. _divergence-unresolved-type:

未解析类型
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``MapType`` 在符号表找不到类型时返回 base 原文；最终可能生成非法 Java。常见原因：

- 忘记加载标准库；
- 简单名歧义（双 ``集合``）；
- 类型名拼写错误；
- 泛型实参缺失/非法。

.. _divergence-no-cleanup:

输出目录不清理
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

编译器不会删除输出目录中的旧文件；重命名/删除类后旧 ``.java`` 可能残留。建议编译前清空输出目录。

.. _divergence-line-map:

行号表覆盖
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

TSM 行号表覆盖主类；异步上下文类与泛型特化文件通常没有 ``line_refs``。不要依赖这些文件的堆栈还原。

.. _divergence-types-names:

``短整数`` 与 ``逻辑``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- 当前没有 ``短整数`` 类型；有 ``字节``、``字符``、``整数``、``长整数``、``单精度小数``、``小数``。
- 布尔类型名是 ``逻辑型``，不是 ``逻辑``；``逻辑`` 不是标准库别名。

.. _divergence-platform-cli:

被忽略的 CLI 选项
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

当前接受但忽略：``--source``、``--keep-defaults``、``--optimize``、``--log-level``、``--android.legacy.lib.path``。不要依赖它们改变产物。

FTC 默认修正与兼容开关
----------------------

FTC 默认启用以下与参考实现不同的修正；不禁用时，编译器会按 FTC 规则生成可构建、输出安全的产物：

.. list-table:: FTC 默认修正
   :header-rows: 1
   :widths: 26 40 34
   :name: table-ftc-compat

   * - 修正项
     - 默认行为（不禁用）
     - ``--disable-ftc-features`` 时
   * - 泛型特化命名
     - 使用合法 Java 类名 ``类名$实参``\ ，文件名/import/调用点一致
     - 使用泛型类或特化时报 ``compat.ftc.generic``
   * - 运算符方法名
     - 映射为 ``operator_*``\ 合法 Java 方法名
     - 使用运算符重载方法时报 ``compat.ftc.operator``
   * - 内联 code 语句
     - 缺少 ``;``/``}`` 时自动补分号
     - 缺少结尾时报 ``compat.ftc.inline-semicolon``
   * - map 键值遍历
     - 发射 ``entrySet()``/``getKey()``/``getValue()``
     - 使用键值遍历会报错（可能先命中泛型检查）
   * - 负步长计次循环
     - 使用 ``>`` 条件，支持倒序
     - 静态负步长报 ``compat.ftc.negative-step``
   * - 对象下标交换
     - 读取两侧值并分别写回两侧下标
     - 使用两侧对象下标交换时报错（可能先命中运算符检查）
   * - 重复订阅事件
     - 同一方法内去重，只注册一次
     - 第二次 ``订阅事件`` 报 ``compat.ftc.subscriptions``
   * - 原始类型事件默认值
     - ``字符``/``字节``/``短整数`` 返回零值
     - 此类事件报 ``compat.ftc.event-default``
   * - 输出路径安全
     - 类 ``@输出名`` 必须合法，且写入限制在输出目录内
     - **始终启用**\ ；安全边界不随兼容开关关闭

如果考虑与参考实现兼容，建议加 ``--disable-ftc-features``。禁用后，依赖上述 FTC 命名/分号修正的代码会显式报错，而不会退化为参考实现的非法 Java 产物或路径穿越。输出目录包含检查是安全边界，始终生效。

局部变量默认值、整数折叠、八进制字面量、``@属性读``/``@属性写`` 注解形式、数组 ``.长度``、异步条件/``假如`` 等规范支持的修正默认启用，不属于该兼容开关的范围。
